# دورك — منصة حجز وإدارة مواعيد

نسخة MVP تجريبية كاملة لمنصة **دورك**: واجهة عربية RTL متجاوبة، تسجيل حسابات العملاء، حجز موعد مسبق، رفع إيصال العربون، ولوحة Admin واحدة لإدارة الحجوزات والخدمات والأسعار وساعات العمل والإجازات.

## التقنية المستخدمة

- **Frontend:** React + Vite + CSS.
- **Backend:** Node.js + Express REST API.
- **Database:** SQLite المدمج في Node (`node:sqlite`) بدون أي مكتبات تحتاج بناء، ويتم إنشاء قاعدة البيانات تلقائيًا عند أول تشغيل.
- **Authentication:** كلمات المرور محفوظة باستخدام `bcryptjs`، وتسجيل الدخول بجلسة JWT داخل Cookie من نوع HttpOnly.
- **Uploads:** صور الإيصالات محفوظة في مجلد غير عام، ولا يمكن عرضها إلا من خلال Endpoint محمي للـ Admin.
- **Validation:** التحقق من البيانات في السيرفر، حد لحجم صورة الإيصال (5MB)، وتحديد محاولات تسجيل الدخول.

> يتطلب المشروع Node.js 22.13 أو أحدث (لاستخدام SQLite المدمج). لا يحتاج Visual Studio ولا Python. قد يظهر تحذير Experimental عند التشغيل وهو طبيعي.

## تشغيل المشروع محليًا على Windows

1. فك ضغط المشروع وافتح PowerShell داخل مجلد `dorak`.
2. أنشئ ملف إعدادات محلي:

   ```powershell
   Copy-Item .env.example .env
   ```

3. افتح `.env` وغيّر `ADMIN_PASSWORD` و`JWT_SECRET` إلى قيم خاصة بك **قبل أول تشغيل**.
4. ثبّت الحزم:

   ```powershell
   npm install
   ```

5. شغّل الواجهة والباك إند معًا:

   ```powershell
   npm run dev
   ```

6. افتح الموقع على `http://localhost:5173`.

الـ API يعمل على `http://localhost:4000`، والواجهة تمرر طلبات `/api` إليه تلقائيًا عن طريق Vite.

## حساب المسؤول التجريبي

القيم الافتراضية في `.env.example` هي:

- اسم المستخدم: `admin`
- كلمة المرور: `Dorak@12345`

**هذه القيم للتجربة المحلية فقط.** غيّر كلمة المرور في `.env` قبل أول تشغيل، ثم سجّل الدخول من زر «تسجيل الدخول». يستطيع المسؤول أيضًا تغيير كلمة مروره من لوحة الإدارة ← «المواعيد والإعدادات».

إذا تم إنشاء قاعدة البيانات بالفعل، تغيير `ADMIN_PASSWORD` في `.env` وحده لا يعيد ضبط كلمة المرور المخزنة؛ استخدم نموذج تغيير كلمة المرور داخل لوحة Admin. لا تحذف قاعدة البيانات إذا كان بها حجوزات تريد الاحتفاظ بها.

## بناء نسخة الإنتاج محليًا

بعد تثبيت الحزم، شغّل:

```powershell
npm run build
npm start
```

سيخدم Express واجهة `client/dist` والـ API من نفس العنوان عند التشغيل في وضع الإنتاج. غيّر `NODE_ENV` في `.env` إلى `production` قبل تنفيذ `npm start`. عند النشر يجب تشغيل الموقع خلف HTTPS وضبط:

```env
COOKIE_SECURE=true
JWT_SECRET=اكتب_قيمة_عشوائية_طويلة_وخاصة
ADMIN_USERNAME=اسم_مسؤول_خاص
ADMIN_PASSWORD=كلمة_مرور_قوية_وخاصة
```

لا تضع ملف `.env` أو قاعدة البيانات أو صور الإيصالات داخل مستودع عام.

## تجربة رحلة العميل

1. من الصفحة الرئيسية اضغط «احجز موعدك».
2. أنشئ حساب عميل: الاسم، الموبايل، اسم مستخدم وكلمة مرور.
3. اختار الخدمة والتاريخ والوقت المتاح، ثم أكّد الطلب.
4. الوضع الافتراضي لا يطلب عربونًا؛ يتم تأكيد الحجز مباشرة.
5. لتجربة مراجعة الإيصالات: سجّل دخول Admin، ثم افتح «المواعيد والإعدادات»، فعّل العربون واكتب بيانات التحويل ومبلغ العربون. ارجع لحساب العميل واحجز مرة أخرى وارفع صورة JPG أو PNG أو WEBP لا يتجاوز حجمها 5MB.
6. من لوحة Admin ← «الحجوزات»، افتح «راجع الإيصال»، ثم اقبل أو ارفض. قبول الإيصال يؤكد الحجز، والرفض يلغي الحجز ويحرر الفترة الزمنية.
7. من لوحة Admin تقدر كذلك تعدّل الحجز والخدمة والسعر ومدة الخدمة وساعات العمل، أو تضيف يوم إجازة، وتحدّث حالة العميل إلى «وصل العميل» ثم «مكتمل».

## البيانات الافتراضية

يتم إنشاء 4 خدمات تجريبية عند أول تشغيل فقط. عدّل أسماءها وأسعارها ومددها من لوحة Admin. ساعات العمل الافتراضية من 12 ظهرًا حتى 12 منتصف الليل، والفاصل بين بدايات المواعيد 30 دقيقة. يأخذ النظام مدة الخدمة في الاعتبار قبل عرض الفترة كمتاحة.

قاعدة البيانات تحفظ في `server/data/dorak.db`، وصور الإيصالات الخاصة في `server/uploads/`.

## ملاحظات وحدود النسخة التجريبية

- مراجعة العربون **يدوية**: رفع الصورة لا يعني أن التحويل تم فعلًا. على المسؤول التأكد من وصوله من وسيلة الدفع قبل القبول.
- لا توجد بوابة دفع إلكتروني أو SMS/WhatsApp تلقائية في هذه النسخة. حالة الحجز تظهر داخل حساب العميل ولوحة المسؤول.
- النظام الآن مبنى واحد بعدة عيادات، لكل عيادة أطباء وخدمات، والمواعيد تُحسب لكل دكتور، ويديره مسؤول واحد فقط. البيانات الأولية (6 عيادات و8 أطباء) تجريبية، عدّلها أو أوقفها من لوحة الإدارة.
- صفحة المطوّر: رابط `#/portfolio` من التذييل. عدّل `client/src/portfolio.config.js` وضع ملف السيرة في `client/public/cv.pdf`.
- لا تعتمد على كلمة المرور الافتراضية أو إعدادات التطوير في بيئة عامة. قبل الإطلاق الفعلي يلزم مراجعة أمنية، واختبار كامل على بيئة الاستضافة، وخطة نسخ احتياطي لقاعدة البيانات والإيصالات.

## رسائل واتساب للعملاء (بدون اشتراكات)

بجانب كل حجز في لوحة Admin زرّان دائمان:

- **«تأكيد الحجز»** (أخضر): يتفعّل لما يكون الحجز «مؤكد» أو «وصل العميل».
- **«إلغاء الحجز»** (أحمر): يتفعّل لما يكون الحجز «ملغي»، سواء ألغاه العميل من حسابه أو ألغاه المسؤول أو رُفض إيصاله.

الزر المنطبق على حالة الحجز فقط هو اللي يشتغل، والتاني يظهر معطّلًا مع توضيح، عشان ما يتبعتش «تم التأكيد» لحجز ملغي بالغلط. الزر يفتح واتساب برسالة جاهزة لرقم العميل، والمسؤول يراجعها ويضغط إرسال بنفسه، فلا يوجد API ولا اشتراك. النصوص في `client/src/whatsapp.js`، ولو رقم العميل غير صالح يظهر الزر معطّلًا.

## سياسة الإلغاء

المسؤول يكتب نص السياسة من «المواعيد والإعدادات» ← العربون ← **سياسة الإلغاء** (الافتراضي: «العربون غير مسترد في حالة إلغاء الحجز.»). تظهر للعميل في ثلاثة أماكن، وكلها لما يكون العربون مفعّلًا:

1. في صندوق العربون قبل ما يأكد الحجز.
2. في حجوزاتي وفي رسالة التأكيد قبل الإلغاء.
3. في رسالة واتساب الإلغاء، لو الحجز عليه عربون.

النص ده إعلان للعميل فقط، والموقع لا يرد أو يحتجز أي مبلغ. وفي حالة التسويات أو الاستثناءات القرار للمسؤول.

## النسخة الاحتياطية

من لوحة Admin ← «المواعيد والإعدادات» ← **«تنزيل نسخة احتياطية»** يتنزل ملف ZIP على جهاز المسؤول فيه:

- `data.json`: كل البيانات (بدون كلمات المرور).
- `bookings.csv`: الحجوزات، يفتح مباشرة في Excel بالعربي.
- `receipts/`: صور الإيصالات باسم كود الحجز.

اللوحة تذكّر المسؤول لو آخر نسخة من هذا الجهاز مر عليها 30 يومًا أو أكثر. الملف فيه بيانات عملاء فاحفظه في مكان خاص. النسخة تُبنى في الذاكرة، وهذا مناسب للنسخة التجريبية.

## مسارات API الأساسية

| Method | Endpoint | الاستخدام |
|---|---|---|
| `POST` | `/api/auth/register` | إنشاء حساب عميل |
| `POST` | `/api/auth/login` | تسجيل الدخول للعميل أو المسؤول |
| `GET` | `/api/auth/me` | معرفة المستخدم الحالي |
| `GET` | `/api/public/services` | الخدمات النشطة |
| `GET` | `/api/public/slots` | عرض فترات اليوم المتاحة أو المحجوزة |
| `POST` | `/api/bookings` | إنشاء حجز، مع صورة إيصال اختيارية/إلزامية حسب الإعدادات |
| `GET` | `/api/bookings/mine` | حجوزات العميل الحالي |
| `GET` | `/api/admin/summary` | ملخص لوحة المسؤول |
| `GET` | `/api/admin/bookings` | قائمة الحجوزات مع فلترة وبحث |
| `PATCH` | `/api/admin/bookings/:id` | تعديل بيانات حجز |
| `POST` | `/api/admin/bookings/:id/payment-review` | قبول/رفض إيصال العربون |
| `GET/POST` | `/api/admin/services` | عرض الخدمات وإضافة خدمة |
| `PATCH/DELETE` | `/api/admin/services/:id` | تعديل خدمة أو إيقافها |
| `PUT` | `/api/admin/settings` | ساعات العمل والعربون والإعدادات |
| `POST` | `/api/admin/blocked-dates` | إضافة يوم إجازة |
| `POST` | `/api/admin/account/password` | تغيير كلمة مرور Admin |
| `GET` | `/api/admin/backup` | تنزيل نسخة احتياطية ZIP (data.json + bookings.csv + الإيصالات) |

كل مسارات `/api/admin` محمية بدور Admin، وصور الإيصالات لا تُخدّم من مجلد عام.
